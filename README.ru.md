Видео цветными символами. Полноценный плеер для браузера: управление, настройки, субтитры, горячие клавиши, картинка в картинке и полный экран, а каждый кадр перерисовывается символами шейдером WebGL2. Сервер может присылать вместо видео сами символьные кадры, и браузер получает компактный поток `.gcast`, а не исходное видео. Тот же поток играет и в терминале.

```sh
npm install glyphcast
```

```html
<script type="module">import 'glyphcast/element';</script>

<glyph-player src="movie.mp4" cols="160"></glyph-player>
<glyph-player src="movie.gcast" audio="movie.m4a" subtitles="movie.vtt"></glyph-player>
<glyph-player youtube="https://youtu.be/…" server="http://127.0.0.1:8787"></glyph-player>
```

Без сборщика: `import 'https://cdn.jsdelivr.net/npm/glyphcast@0/dist/element.js/+esm'`.

## Плеер

`<glyph-player>` играет видео, камеру, локальные файлы и потоки `.gcast`. Внутри: воспроизведение и пауза, ±10 секунд, полоса перемотки с загруженной частью и подсказкой времени, громкость, скорость, картинка в картинке (через Document PiP весь плеер целиком, где браузер это умеет, иначе только изображение), полный экран и меню настроек: ширина сетки, способ отрисовки (символы, точки Брайля или растр), набор символов, цвет, насыщенность, автоуровни, контуры и кинескоп. С контурами клетки на границах предметов рисуются символами `- / | \` по направлению границы, а кинескоп добавляет строки развёртки, виньетку и свечение. Во время воспроизведения панель прячется.

| Атрибут | |
|---|---|
| `src` | Ссылка на видео или файл `.gcast` |
| `poster` | Картинка, которая видна до первого кадра |
| `audio` | Звук для файла `.gcast` |
| `youtube`, `file`, `server` | Поток через `glyphcast serve` (см. ниже) |
| `subtitles` | Субтитры WebVTT или SRT, рисуются той же сеткой символов |
| `cols` | Ширина сетки в символах, по умолчанию `160` |
| `glyphs` | Символы от тёмного к светлому, по умолчанию `' .:-=+*#%@'` |
| `tint` | Один цвет для всех символов, например `#33ff66` |
| `boost` | Насыщенность, по умолчанию `1.3` |
| `autolevels` | `false` выключает подстройку яркости и контраста |
| `mode` | `glyphs`, `braille` или `halftone` |
| `edges`, `crt` | Контуры и вид кинескопа |
| `fill` | Подсветка фона клетки её цветом, от 0 до 1, по умолчанию `0.25` |
| `autoplay`, `muted`, `loop` | Как у `<video>` |

Клавиши: пробел или K пауза, ←/→ 5 с, J/L 10 с, ↑/↓ громкость, M звук, F полный экран, P картинка в картинке, 0–9 переход. Оформление меняется через `--accent` и `--radius`; `element.load(файлПотокИлиСсылка)` и `element.player` дают управление из кода.

### React и Vue

```tsx
import { GlyphPlayer } from 'glyphcast/react';

<GlyphPlayer src="/movie.gcast" poster="/movie.jpg" mode="braille" onReady={(player) => player.play()} />
```

```vue
<script setup>
import { GlyphPlayer } from 'glyphcast/vue';
</script>

<template>
  <GlyphPlayer src="/movie.gcast" poster="/movie.jpg" mode="braille" @ended="next" />
</template>
```

Пропсы те же, что атрибуты (`autoPlay`, `autoLevels` в camelCase), плюс события `play`, `pause`, `ended`, `timeupdate`, `error` и `ready` с движком. Элемент подгружается после монтирования, поэтому обёртки работают и с серверным рендерингом.

Без интерфейса тот же движок называется `GlyphPlayer` и повторяет API медиаэлемента: `load`, `play`, `pause`, `seek`, `currentTime`, `duration`, `volume`, `muted`, `playbackRate`, `configure(look)`, `setCaptions(текстИлиСсылка)` и привычные события.

## Символы вместо видео

При 160 колонках кадр состоит примерно из девяти тысяч цветных клеток, это намного меньше кадра видео. `.gcast` хранит у каждой клетки яркость (6 бит), а цвет один на квадрат 2×2 клетки, как 4:2:0 в видео. Сетка нарезана на блоки 8×4: блок либо повторяет прошлый кадр со сдвигом (вектор движения), либо несёт остаток к нему, огрублённый до порога. Куски по одной-две секунды сжимаются deflate и начинаются с точного опорного кадра. Звук можно вшить прямо в `.gcast`: он идёт перед кадрами, плеер достаёт его и ведёт по нему время. В песочнице есть конвертер, который делает `.gcast` из вашего видео прямо в браузере (кодирование идёт в Web Worker) и показывает, во сколько раз файл стал меньше, а рядом готовую команду для консоли. Целые фильмы лучше конвертировать в консоли: браузер не удержит в памяти их звук. В конце файла лежит индекс кусков: плеер читает его range-запросом и при перемотке сразу качает нужное место, не дожидаясь загрузки всего файла. Формат потоковый: у кусков есть длина, поэтому плеер начинает с первого же куска, а сервер может выдавать их на лету.

```sh
npx glyphcast encode movie.mp4 --cols 180 --embed --poster    # один файл со звуком Opus внутри и постер movie.jpg
npx glyphcast encode *.mp4 --embed                            # несколько видео подряд, с прогрессом и оставшимся временем
npx glyphcast encode movie.mp4 --cols 180 --audio movie.m4a   # звук отдельным файлом
npx glyphcast hub                                               # видео в gcast hub, смотреть: npx glyphcast play hub:имя
npx glyphcast play movie.gcast                                  # в терминале: пробел пауза, ←/→ перемотка, M отрисовка, G символы, C цвет, [ ] насыщенность, B фон, Q выход
npx glyphcast serve --dir ./videos                              # живые потоки
npx glyphcast micro movie.mp4 --cols 180                        # крошечное H.264 размером с сетку
```

`glyphcast serve` превращает ссылки на YouTube (через yt-dlp) и видео из папки `--dir` в живые потоки `.gcast` с отдельным звуком Opus, перематывает, перезапуская поток с нужной секунды, и отдаёт готовые файлы с поддержкой range-запросов. Слушает только `127.0.0.1`. Браузер сам не может читать кадры YouTube, поэтому YouTube работает именно через этот сервер. `glyphcast play` принимает и ссылку на такой поток, так что YouTube можно смотреть прямо в терминале.

Минута фильма, только картинка:

| Что отправляется | Размер | Битрейт |
|---|---|---|
| Исходник, 1280×544 H.264 (сильно сжатый) | 4,9 МБ | 650 кбит/с |
| `.gcast` v2 (0.2), 180 колонок, 30 к/с | 2,07 МБ | 276 кбит/с |
| `.gcast` v3, 180 колонок, 24 к/с | 1,15 МБ | 153 кбит/с |
| `.gcast` v3, 180 колонок, 15 к/с | 0,90 МБ | 120 кбит/с |
| `.gcast` v3, 120 колонок, 24 к/с | 0,57 МБ | 78 кбит/с |
| Микровидео, 180 колонок H.264 | 0,35 МБ | 47 кбит/с |

Размер потока зависит от сетки и движения в кадре, а не от разрешения исходника, поэтому чем тяжелее исходник, тем больше выигрыш. Микровидео всё равно меньше: у видеокодеков есть DCT и энтропийное кодирование, которых у `.gcast` нет. Зато `.gcast` не нужен видеодекодер, он даёт одинаковые кадры везде, и его можно генерировать или править покадрово. В Node модуль `glyphcast/node` даёт `encodeVideo`, `encodeMicroVideo`, `extractAudio` и `serve`, а `Encoder` собирает поток из сырых кадров любого источника.

## Хаб

[gcast hub](https://mrprolopstar.github.io/gcast-hub/) хранит видео в `.gcast` и показывает их в браузере. Те же видео играют в консоли:

```sh
npx glyphcast hub                  # список и поиск
npx glyphcast play hub:<имя>       # смотреть со звуком, паузой и перемоткой
```
