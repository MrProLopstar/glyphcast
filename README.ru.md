# glyphcast

[![npm](https://img.shields.io/npm/v/glyphcast?color=f0a04b)](https://www.npmjs.com/package/glyphcast)
[![JSR](https://jsr.io/badges/@mrprolopstar/glyphcast)](https://jsr.io/@mrprolopstar/glyphcast)

[English version](README.md) · [Песочница](https://mrprolopstar.github.io/glyphcast/)

Видео цветными символами. Полноценный плеер для браузера: управление, настройки, горячие клавиши, картинка в картинке и полный экран, а каждый кадр перерисовывается символами шейдером WebGL2. Сервер может присылать вместо видео сами символьные кадры, и браузер получает компактный поток `.gcast`, а не исходное видео.

```sh
npm install glyphcast
```

```html
<script type="module">import 'glyphcast/element';</script>

<glyph-player src="movie.mp4" cols="160"></glyph-player>
<glyph-player src="movie.gcast" audio="movie.opus"></glyph-player>
<glyph-player youtube="https://youtu.be/…" server="http://127.0.0.1:8787"></glyph-player>
```

Без сборщика: `import 'https://cdn.jsdelivr.net/npm/glyphcast@0/dist/element.js/+esm'`.

## Плеер

`<glyph-player>` играет видео, камеру, локальные файлы и потоки `.gcast`. Внутри: воспроизведение и пауза, ±10 секунд, полоса перемотки с загруженной частью и подсказкой времени, громкость, скорость, картинка в картинке (через Document PiP весь плеер целиком, где браузер это умеет, иначе только изображение), полный экран и меню настроек: ширина сетки, набор символов, цвет, насыщенность и автоуровни. Во время воспроизведения панель прячется.

| Атрибут | |
|---|---|
| `src` | Ссылка на видео или файл `.gcast` |
| `audio` | Звук для файла `.gcast` |
| `youtube`, `file`, `server` | Поток через `glyphcast serve` (см. ниже) |
| `cols` | Ширина сетки в символах, по умолчанию `160` |
| `glyphs` | Символы от тёмного к светлому, по умолчанию `' .:-=+*#%@'` |
| `tint` | Один цвет для всех символов, например `#33ff66` |
| `boost` | Насыщенность, по умолчанию `1.3` |
| `autolevels` | `false` выключает подстройку яркости и контраста |
| `autoplay`, `muted`, `loop` | Как у `<video>` |

Клавиши: пробел или K пауза, ←/→ 5 с, J/L 10 с, ↑/↓ громкость, M звук, F полный экран, P картинка в картинке, 0–9 переход. Оформление меняется через `--accent` и `--radius`; `element.load(файлПотокИлиСсылка)` и `element.player` дают управление из кода.

Без интерфейса тот же движок называется `GlyphPlayer` и повторяет API медиаэлемента: `load`, `play`, `pause`, `seek`, `currentTime`, `duration`, `volume`, `muted`, `playbackRate`, `configure(look)` и привычные события.

## Символы вместо видео

При 160 колонках кадр состоит примерно из девяти тысяч цветных клеток, это намного меньше кадра видео. `.gcast` хранит их 12-битными цветами в байтовых плоскостях, пропускает клетки, которые почти не изменились, и сжимает куски по одной-две секунды, каждый из которых начинается с опорного кадра. Формат потоковый: у кусков есть длина, поэтому плеер начинает с первого же куска, а сервер может выдавать их на лету.

```sh
npx glyphcast encode movie.mp4 --cols 180 --audio movie.opus   # файл и звук
npx glyphcast serve --dir ./videos                              # живые потоки
npx glyphcast micro movie.mp4 --cols 180                        # крошечное H.264 размером с сетку
```

`glyphcast serve` превращает ссылки на YouTube (через yt-dlp) и видео из папки `--dir` в живые потоки `.gcast` с отдельным звуком Opus, перематывает, перезапуская поток с нужной секунды, и отдаёт готовые файлы с поддержкой range-запросов. Слушает только `127.0.0.1`. Браузер сам не может читать кадры YouTube, поэтому YouTube работает именно через этот сервер.

Для ролика длиной 117 секунд:

| Что отправляется | Размер | Битрейт |
|---|---|---|
| Исходное видео, 1280×720 H.264 | 38,8 МБ | 2,66 Мбит/с |
| `.gcast`, 180×61 символов, только картинка | 3,6 МБ | 254 кбит/с |
| Микровидео, 180×60 H.264 со звуком AAC | 1,7 МБ | 117 кбит/с |

Микровидео ещё меньше, потому что видеокодеки предсказывают движение; зато `.gcast` не нужен видеодекодер, он даёт одинаковые кадры везде, и его можно генерировать или править покадрово. В Node модуль `glyphcast/node` даёт `encodeVideo`, `encodeMicroVideo`, `extractAudio` и `serve`, а `Encoder` собирает поток из сырых кадров любого источника.
